Main State Sequence

  • 1. BROADCASTING — Job posted, radius = 25km
  • 2. QUOTES_RECEIVED — Workers submit bids
  • 3. ALLOCATED — Customer accepts one quote
  • 4. ARRIVING — Worker travels, streams GPS
  • 5. IN_PROGRESS — Work executing, chat active
  • 6. COMPLETED — Worker marks done, escrow LOCKED
  • 7. PAID — Admin verifies UTR, settlement fires
  • 8. CLOSED — Both sides rated, terminal

Side Exits

  • CANCELLED 3 broadcast rounds → 75km → auto-cancel
  • CANCELLED 2h in QUOTES_RECEIVED → cron sweeper
  • CANCELLED Customer cancels pre-allocation
  • DISPUTED Either party during/after job
  • Dispute resolution: DEDUCT_FROM_WORKER / WAIVE_FEE / REFUND_CUSTOMER / CLOSE

Settlement (settleJobCompletion)

  • Trigger Job transitions to PAID
  • Worker 100% of agreed amount credited
  • Platform 10% commission → treasury
  • GST Tax ledger entry
  • Idempotent settle_job_{id} unique sparse index
  • Atomic findOneAndUpdate prevents double-settlement

Security & Anti-fraud

  • OTP 4-digit, crypto.timingSafeEqual (timing-safe)
  • Location Redis anti-spoof: only assigned worker may stream
  • UTR 12-digit, dummy-pattern blacklist at all layers
  • Zero-trust All UPI inflows PENDING until admin bank-verify
  • Replay Unique UTR index in WorkerSubscription model
